## 2. 同步最新构建产物的规则

1. **插件 DLL**：以当前游戏部署版为准（`BepInEx\plugins\LocalModManager.dll`），同步进包后 **MD5 必须与部署版一致**（`certutil -hashfile <file> MD5`）。部署版的备份惯例在 `KIMI\backup_deployed_pre_*.dll`。
2. **bat**：一律从 `KIMI\bepinex_plugin\`（或 bat 源目录）取最新版，禁止手改包内旧 bat。
3. **modlauncher / modprobe**：重建后先在本机实测一轮启动，再进包。
4. **BepInEx\cache\chainloader_typeloader.dat**：随包走，无特殊情况不动。
5. **interop\**：插件重新生成过才需要同步；否则不动。

## 3. bat 硬性规范（踩过坑，逐条执行）

1. 编码 **GBK（ANSI）**，行尾 **CRLF**。用 Python 检查：
   ```python
   data = open(bat, 'rb').read()
   assert b'\r\n' in data and b'\n' not in data.replace(b'\r\n', b'')
   data.decode('gbk')  # 不抛异常即编码正确
   ```
2. 所有路径变量引用必须带引号：`"!GAME!"` 而不是 `!GAME!`。
3. **合法但易误判的写法**（扫描器看到 `\"` 别紧张）：
   - `set "GAME=!GAMEINPUT!\"`（目录尾反斜杠）
   - `...WorldApart_mod_Data\"`（同理）
4. 中文 echo 行在 GBK 下直接写，不要存成 UTF-8（否则对方设备报 `'[安装]' 不是内部或外部命令`）。

## 4. 零 kimi 残留扫描

发布包内任何用户可见字符串 / 文件名 / 日志前缀**不得出现 kimi**（`A1\KIMI` 工作目录本身不受影响）：

```python
# 文件名扫描：逐文件名检查（os.walk），含 zip 内条目名
# 文本扫描：对 md/bat/json/txt/cs 等按 gbk/utf-8 解码后搜 'kimi'（大小写不敏感）
```

**已知误报，确认后放行**：
- `.zip` 压缩数据内部的字节命中（条目名干净即可）——典型：`unity-libs\2022.3.43.zip`。
- `dotnet\System.Text.Encoding.CodePages.dll` 等二进制内的字符表巧合命中。
- DLL 内嵌 PDB 调试路径：必须在插件 csproj 加 `<DebugType>none</DebugType>` 消除，**不允许靠放行**。

## 5. 打 zip（重要：禁用 bash/ps1 旧脚本）

- `KIMI\release\make_zip.ps1` / `run_make_zip.ps1` **已失效**（硬编码旧包名，且 bash 的 `rm -f *.zip` 对中文文件名静默失败，曾导致旧 zip 残留被误改名）。
- 一律用 Python zipfile：

```python
import os, zipfile
pkg = r'<G>\KIMI\release\不问凡尘_MOD环境_v1.6'
out = pkg + '.zip'
with zipfile.ZipFile(out, 'w', zipfile.ZIP_DEFLATED) as z:
    for dirpath, _, files in os.walk(pkg):
        for f in files:
            p = os.path.join(dirpath, f)
            z.write(p, os.path.relpath(p, pkg))
# 校验：条目数应与 os.walk 文件数一致
```

## 8. 已知环境坑速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 对方设备 `'/p' 不是内部或外部命令` | bat 是 UTF-8 / LF / 引号缺失 | 回 §3 重新规范 |
| 中文文件名 zip 残留 / 改名错乱 | bash 对中文文件名不可靠 | 文件操作一律 Python |
| `FINDSTR: 无法打开 xxx` | cmd 管道编码（GBK 控制台） | 用 Python subprocess + decode('gbk') |
| 对方设备 `Failed to load il2cpp` | 与本 MOD 环境无关（Unity 播放器自身报错） | 见实施报告 v6r2 §6 |
| `spawn helper err=2/5` | modlauncher 旧构建 | 用 v1.6 的 modlauncher/modprobe |
