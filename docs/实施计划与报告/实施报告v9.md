### 1.4 受控复现尝试（"克隆体"对照实验）与结论

历史 6 份日志的**全部**命中都来自 MODTab 是 `Instantiate(Frame#navSystem)` 克隆体的构建
（v7 报告 §3 与源码 S2 注释互相印证：克隆体带 UPF 元素身份，被 UPF 布局引擎当成"同一个
标签的又一个实例"逐帧重排，v7 的 MODTab 因此停在列的原始锚点、不可见）；现役 v1.6 已改为
**从零新建 GameObject**（`Plugin.cs` `S2 fix: do NOT clone navSystem`），并在其上
`navigation.mode=None`、`transition=None`。

为做 A/B，本轮写了 `TabCloneRecon.cs`（recon，只在
`MOD_TAB_DIAG=1 MOD_TAB_DIAG_CLONE=1` 时生效）试图重建 v7 那种克隆体。结果：

```
[DBG] TABCLONE clone has no Button anywhere; root=RectTransform Component … __BackgroundImage[Transform,Component,Component] …
      | template=RectTransform … Image … __BackgroundImage[Transform,Component,Image] …
```

即 `Object.Instantiate` 出来的克隆体，其组件在 Il2CppInterop 下**退化成共享桩类型**
（`GetType().Name` 只剩 `Component`），`GetComponent<Button>()` / `GetComponent<Image>()`
都取不到，**无法从中托管侧重新接回点击通路**。这条对照路线因此无法产出"克隆体被触发"的
日志；该现象本身也佐证了克隆体在本运行时里是"二等对象"。

**根因定论（H2，置信度高，但需声明证据强度）**：
`[SETTINGS] MOD tab clicked mouseDown=False` 的触发体，是 **MODTab 作为 `Frame#navSystem`
克隆体时携带的 UPF 元素身份**。游戏自己的标签列刷新/激活动作（委托方日志里同一刻把
`ActivePage` 从 `audio` 驱动到 `system`）沿 UPF 身份命中了这个"同身份的另一个实例"，
把它的 `Button.onClick` 一并点了；因为不是指针事件，`Input.GetMouseButton(0)` 为 False。
v1.6 的 S2 变更（不再克隆、不给新节点任何 UPF 身份）从根上移除了这条通路：全部 6 份命中
日志都是 S2 之前的构建，S2 之后的构建（v8 验收 + 本轮 3 轮侦察）**零命中**。

**没有采信为根因的假设**（逐条排除依据）：

| 假设 | 判别 | 结论 |
|---|---|---|
| H1 EventSystem Submit（键盘/手柄导航） | 已设 `navigation.mode=None`；诊断日志 `selected=` 与 `module=` 字段在现役构建里从未出现我们标签被选中的记录 | 不作为主因；**仍作为 P1 加固对象**（见 §1.5） |
| H2 克隆体 UPF 身份 | 全部命中日志均为克隆构建；S2 之后零命中；受控复现因 il2cpp 类型桩退化不可行 | **采纳为根因** |
| H3 `Maintain()` 重注入叠按钮 | `[DBG] TABREINJECT` 显示每次面板实例只 `create` 一次、随后 `adopt-existing`；`[DBG] TABCLICK … btns= imgs= modTabNodes=` 字段在现役构建中恒为 1/2/1 | 排除 |
| H4 v8 滚动链（`ScrollRect.OnScroll` 钩子） | `lastWheelDt` 字段：命中时刻离最近一次滚轮钩子调用为「从未/极远」；且 S2 之后（含 v8 滚动修复上线后）零命中 | 排除；**不影响滚动修复行为**（见 §1.6 R3） |
| H5 真实键盘/手柄误触 | 所有命中均为无人工操作的自动轮次 | 排除 |

**声明影响面**：本轮 P1 修复**不触碰** v8 滚动链（`NativeWheelConsumerHook` / MOD 页滚动条）
任何行为，只改了 `OnModTabClicked` 的入口门与 `ManagerWidget.Update` 一行记录。

### 1.5 P1 修复：真实指针门

`SettingsEntryHook.OnModTabClicked` 入口（保留原有第一行日志不动，便于 R1 计数）：

```csharp
float since = Time.unscaledTime - _lastPointerDownAt;
bool pressedRecently = since >= 0f && since <= 0.3f;
if (!pressedRecently && !Input.GetMouseButtonUp(0))
{
    Plugin.Logger.LogInfo("[SETTINGS] MOD tab click ignored (no real pointer) t=… sinceMouseDown=… mouseUp0=…");
    return;                       // 丢弃：不是真实指针点击
}
ModPageController.Toggle(_panel);
```

`_lastPointerDownAt` 由 `ManagerBehaviour.Update` 每帧
`if (Input.GetMouseButtonDown(0)) SettingsEntryHook.NoteMouseDown();` 记录
（一次 `Input` 调用/帧，与既有 `Input.GetKeyDown(F10)` 同级开销）。

- 真实鼠标点击：按下发生在点击前 ~0.1 s，恒在 0.3 s 窗口内 → **行为不变**。
- Submit（键盘/手柄导航）/ 任何代码 `Press()`、`onClick.Invoke()`：无按下记录 → 丢弃。

**结论（P3）**：

1. v7 的 `TryStartQuestProc 返回 False` **不是入口本身的问题**，而是 harness 直调
   `GameStoreManager.LoadCurrentSlot` 绕过了正常入世界时序，导致
   (a) `LubanExprManager` 宏命名空间未绑定 → 流程脚本加载/任务表翻译失败；
   (b) 无世界会话来宾 → 任何业务 proc 拒绝启动。
   两条都由**游戏自己的异常文本**证明，已在本轮驱动里补齐（`LogOutput_P3D`/`P3G` 可见）。
2. 补齐后 **`TryStartQuestProc` 仍然返回 False**（任务 Available、flows loaded=True、
   世界会话已发布、`HasAnyObjectiveFlow=True`）→ **该入口在本构建里不能作为外部"起某任务剧情流程"
   的入口**，v7 §7.1 的备选 `FlowRuntimeManager.Instance.StartInWorld(...)` 同理被
   "无世界会话"一票否决（同一判据）。
3. **可用的路线是游戏自己的 `QuestManager.DebugForceAcceptQuest`**：返回 True，
   任务 Available→InProgress，**调度器 `quiescent=True → False`**（有 proc 真的在跑）。
   F9「剧情跳跃」区因此已按此证据调整为先调 `TryStartQuestProc`、失败再走
   `DebugForceAcceptQuest`（只在既有剧情跳跃区内补行为，未改 F9/F10 布局）。
4. **未达成**：`objective settled` 没有前进（0/1）。quest 1001 的 objective#0 是
   "到达 河望镇主街"，需要**玩家真的走到那里**，自动化无法驱动角色移动；且约 +20 s 后
   任务状态被游戏自身回滚为 Available（强制接取缺少正常接取上下文）。
   失败样本已如实保留在 §2.1 各行。

### 6.2 本机环境限制：会话无前台窗口，合成鼠标不可用

本轮发现并留证：该会话的桌面**没有前台窗口**（`GetForegroundWindow()` 返回 `0`），
因此 `SendInput` 被系统拒绝（返回 0，`mouse_event` 亦无效）。四个方向的交叉验证：

| 探针 | 结果 | 含义 |
|---|---|---|
| `GetForegroundWindow()` | `0` | 当前桌面没有前台窗口（锁屏/未连接会话） |
| `SendInput` 返回值 | `0`（失败） | 系统拒绝注入按键事件 |
| `Input.mousePosition` | 跟随 `SetCursorPos` 精确变化（`(601,788)`） | 游戏侧能看到光标位置 |
| `EventSystem` 射线 | `overUI=True`、`hit=MODTab` | 光标确实落在我们的 MOD 标签上 |

→ 位置、命中都正确，唯独"按下"送不进去，因此 **R2 的真实鼠标点击无法脚本化**，
已用 §1.5 的门禁自测替代（功能等价），物理点击留给委托方（§6.3）。
同一限制也意味着**本轮无法产出截图**（v8 用的 `CopyFromScreen` 同样依赖交互桌面），
故 §1.6 R3 的 A2/A5 视觉项只能由委托方复看。
