## 背景事实（已实测，直接采信）

1. **现象**：游戏进行中（设置页不一定打开），MOD 页偶尔自己开/关。插件日志出现
   `[SETTINGS] MOD tab clicked t=<秒> mouseDown=False` —— onClick 被触发但当时左键未按下。
   既有发生记录（每会话 1–2 次，时间点随机 t=27–51s）：
   - `KIMI\v5_final_acceptance.log`：2 次（t=50.95 / 51.84）
   - `KIMI\v6_debugoff.log`：1 次（t=35.90）
   - `KIMI\v6_pre_s3_logoutput.log`：1 次（t=27.48）
   - `KIMI\v7_p0_phase1.log`：2 次（t=28.96 / 32.00）
   v8 滚动修复后尚无新日志样本（迁移打断），无法确认滚动钩子是否影响发生率。
2. **现有实现**（`KIMI\bepinex_plugin\Plugin.cs`）：
   - MOD 标签是克隆 navSystem 标签而来（`SettingsEntryHook`，line ~285），自有 Button 盖在 raycast Image 上，
     监听 `btn.onClick → OnModTabClicked`（line 296/468）→ `ModPageController.Toggle`。
   - 已做过的防护：`onClick.RemoveAllListeners()` 后重挂；`transition=None`；
     `navigation.mode=None`（防键盘/手柄导航 Submit）——**bug 仍出现**，说明触发路径不止导航。
   - `Maintain()` 每 0.25s 检查标签是否被游戏重建并重新注入（line 989/3490）。
   - v8 新增 `NativeWheelConsumerHook`（Harmony prefix 拦 `ScrollRect.OnScroll`）与 MOD 页滚动条，
     与本 bug 共享设置页事件链，改动时需一并回归。
3. **新机环境变化（本次验收发现，实施时知情）**：
   - IFEO 注册被本机安全策略禁止（reg.exe / PowerShell 提权均"拒绝访问"），
     启动只能走 `启动MOD版.bat → modlauncher.exe(=wastart) → WorldApart_mod.exe`，**不要依赖 IFEO**。
   - 注入启动存在偶发崩溃：2 次启动 1 次 `WorldApart_mod.exe` 于 ntdll `0xc0000005`（WER 事件 1000/1001 在档），
     1 次完整成功（`[Mod Manager] loaded`，0 Error）。复跑脚本 `KIMI\v6_run.ps1` 已用
     `WorldApart*` 通配杀进程，崩溃样本会自动重试即可；若崩溃率 >1/3 先取 WER 转储再往下做。

## P0 根因侦察（本计划主体）

目标：拿到一次自发触发的完整现场，用证据从下列假设中定位唯一根因，**不允许未定位先修**。

### 假设清单（按先验排序）

| # | 假设 | 判别方法 |
|---|---|---|
| H1 | EventSystem 的 Submit 路径：`StandaloneInputModule`/游戏自研输入模块把 Submit 发给某个被（重）选中的对象，UPF 层把事件路由到我们的 Button | 诊断日志打 `EventSystem.current.currentSelectedGameObject` 与 `EventSystem.current.currentInputModule` 类型；自触发瞬间若 selected 是我们的标签 → H1 |
| H2 | 克隆标签仍带 UPF 身份/行为驱动，游戏 UPF 系统在标签列重排或刷新时以代码方式触发其 click（v7 克隆体被引擎每帧重排的同类机制） | 诊断日志打 `EventSystem.current.IsPointerOverGameObject()`、当时设置页是否打开、调用栈 |
| H3 | `Maintain()` 重注入时旧 Button 未销毁干净，同一可视标签上叠了第二个带监听器的 Button；或游戏重建标签列后我们的克隆体被原生代码触发 | 诊断日志打 `Time.frameCount`、按钮实例 `GetInstanceID()`、`onClick` 监听器计数；`Maintain` 加"重建时先销毁自己上一版 GameObject"断言 |
| H4 | 滚轮/指针事件链误触发 pointerClick（v8 的 ScrollRect hook 改变事件流后出现或加剧） | 对比 v8 前后发生率的 A/B：`MOD_SCROLLRECON=1` 存档基线 vs 修复运行 |
| H5 | 真实键盘/手柄 Submit（玩家误触，非 bug） | 诊断打 `Input.GetKey` 全键扫描 / `Input.GetJoystickNames`；若自触发时无任何输入且设置页关闭 → 排除 |

### 实现

1. 新增环境开关 `MOD_TAB_DIAG=1`（默认关，零开销首行返回）。`OnModTabClicked` 在开关下输出单行诊断：
   ```
   [DBG] TABCLICK t=<unscaledTime> frame=<n> down=<LMB> selected=<name|null> module=<type>
         pointerOverUI=<bool> settingsOpen=<bool> btnId=<instanceID> listeners=<count>
         stack=<压缩调用栈(前 5 帧类名.方法名)>
   ```
   调用栈用 `Environment.StackTrace` 截前若干行即可，禁止反射遍历进程。
2. `Maintain()` 重注入路径加日志：`[DBG] TABREINJECT reason=<…> oldId=<…> newId=<…>`（仅 MOD_TAB_DIAG=1）。
3. 自动化取样：改 `KIMI\v6_run.ps1` 副本为 `KIMI\v9_run.ps1`，循环启动游戏（`MOD_P2_SELFTEST=1` 自动开设置页 +
   `MOD_TAB_DIAG=1`），每轮 120s，目标累计 ≥6 轮或抓到 ≥2 次自发触发（现役发生率约 1–2 次/会话，6 轮应足够）。
   抓到现场即停，保存 `BepInEx\LogOutput.log` 为 `KIMI\v9_tabdiag_<轮次>.log`。
4. 依据诊断输出锁定假设（预期 H1/H2/H3 之一；若调用栈显示 ExecuteEvents/UPF 路由即可定论）。

## P1 修复（根因定位后）

- **若 H1/H5（Submit 路径）**：`OnModTabClicked` 入口加"真实鼠标释放"门——
  要求 `Input.GetMouseButtonUp(0)` 或最近 0.3s 内有 `Input.GetMouseButtonDown(0)` 记录，否则记一行 diag 后 return；
  手柄/键盘玩家保留：F10 窗内已有开关入口，不单独照顾 Submit。
- **若 H2（UPF 身份）**：MOD 标签改为**从零新建 GameObject**（v7 MOD 页教训的原生扩展：
  只拷 RectTransform 几何与字体/颜色引用，不克隆带 UPF 身份节点），重建点击通路。
- **若 H3（重注入叠加）**：`Maintain()` 重建前先按 `_modTabRect` 引用销毁旧克隆（null 检查 + DontDestroy 例外处理），
  并在注入时断言 `onClick` 非匿名重复（用计数即可）。
- **若 H4（滚动链）**：在 `NativeWheelConsumerHook` 里断点验证事件不进入 pointerClick 路径；
  必要时 MOD 页打开期间对标签 Button 挂 `IEventSystemHandler` 屏蔽层。
- 无论哪条：修复必须保留真实鼠标点击开/关 MOD 页的行为（委托方会复看）。

## P3 剧情跳跃闭环（v7 遗留，本轮必须落地）

   `DebugActions.StartQuestProc`。预期日志：`剧情跳跃请求` → `TryStartQuestProc 返回 True`。
