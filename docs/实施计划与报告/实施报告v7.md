**中途排除的两个实现坑（都留了证据）**

1. **载档必须在配置表就绪之后**。第一次尝试在 `t≈3s` 直接 `LoadCurrentSlot`，抛
   `MessagePack.MessagePackSerializationException: Failed to deserialize Game.Model.GameWorldModel value.`；
   加了"等 `ConfigManager.Tables.TbQuest/TbNpcBaseCfg` 就绪"的门（实测 `t=3.7s` 就绪）后即可正常载档。
   注意 `FlowRuntimeManager.FlowsLoadedAndTranslated` 在主菜单恒为 `False`，**不能**拿它当门（会永远等下去）。
2. **`BagModel.AddItem` 的 4/5 号参数**。`ItemSourceType` 换 4 种值都 `NullReferenceException`；
   用反射打印出 interop 真实签名后按签名构造参数才成功：
   ```
   [DBG] JMP AddItem interop 签名 LubanDatas.data.Item AddItem(LubanDatas.TbItemId, Int32,
        Game.Model.ItemSourceType, Il2CppSystem.Nullable`1[Game.Model.Components.AddItemContext], Il2CppSystem.Action)
   ```
   即第 4 参是 `Il2CppSystem.Nullable<AddItemContext>`（值类型包装），传 C# `null` 会 NRE；
   实现改为 `Activator.CreateInstance(参数类型)` 造默认 Nullable，第 5 参传 `null` 即可。

## 3. P1 路线排除过程（A / B / C）

| 计划路线 | 结论 | 依据（反汇编/全镜像 callscan） |
|---|---|---|
| **A** 钩住地图旅行链上"创建 ProcContext"的调用点，postfix 换目标 spaceId | ❌ **证伪，链上不存在该调用点** | 旅行链为 `BaseMapPoi.OnTriggered(0x1A529E0)` → 派生 `Execute()`(`SpaceMapPoi 0x1A62F90` / `NormalDungeonMapPoi 0x15214A0` / `RogueDungeonMapPoi 0x1525F90` / `WorldBossMapPoi 0x1673650`) → `StartPoiTransferToInstance(0x1A53560)` / `ToDeferredInstance(0x1A53470)` → `<…>d__15/d__16.MoveNext` → `MapPoiTransferPolicyResolver.ConfirmLeaveAsync(0x1A54F10)` → **`StartPoiTransferCore(0x1A530C0)` → `SpaceManager.GotoSpaceInstance(0x15F1190)`**。全程不建 `ProcContext`。另 `GotoSpaceCommand..ctor` 的调用者只有流程表达式构造器（`FlowExprSpace.GotoSpace` 等 5 处），其 `ExecuteAsync(0x15E77D0)` 全镜像 **0 个直接调用者** → 只能由 `FlowScheduler` 虚调用，外部不可直调。 |
| **B** 更下层 API（EnterSpace / SceneLoader 类） | ❌ 不存在可用的公开入口 | 全量正则 `(EnterSpace\|SwitchSpace\|LoadSpace\|TransferTo\|ChangeSpace\|GotoSpace)\w*\(` 扫 dump：`SpaceManager` 上只有 `GotoSpace` / `GotoSpaceInstance` / `EnterBattleSpace` / `BackToParentSpace` / `LeaveBattleSpace`；没有 `SceneLoader`/`WorldLoader`。更下层的 `BaseSpaceHandler.EnterSpace(SpaceTransitionContext)` 需自建上下文（`NeedsSceneLoad` 等位决定场景加载），绕开 `SpaceManager` 极易破坏世界状态 → 不采用。 |
| **C** 程序化驱动游戏自带地图 UI | ❌ 不采用 | 需要 UI 交互 + vtable 分派（`+0x1d8` 槽），且与"不开额外窗口/稳定复现"的目标不符。 |
| **实际落地** | ✅ `Game.SpaceManager.Instance.GotoSpace(Nullable<TbSpaceId>, …)` | 它是旅行链终点前一步（`StartPoiTransferCore` 唯一碰 `SpaceManager` 的调用就是它的子步骤 `GotoSpaceInstance`），**不需要 `ProcContext`、不需要流程脚本、不需要自建过渡上下文**；已有游戏源码级调用形状实证（`TrackingTargetNavigator.Navigate` 只传 spaceId，其余 12 参 0/null）。 |

副作用（需在验收时知情）：直调 `GotoSpace` 跳过 `MapMoveTimeCalculator` 旅行耗时结算、`GuideManager.NotifyStartMapTransfer` 引导提示、`MapPoiTransferPolicyResolver.ConfirmLeaveAsync` 离场确认弹窗。

## 7. 遗留风险

1. **P2 未闭环**：`TryStartQuestProc` 返回 `False`。已知两个干扰项（世界在传送迁移中、目标任务 `activeFlowId=0`）都指向"需要换任务/换时机重测"，但**没有干净的通过证据**。备选路线：`FlowRuntimeManager.Instance.StartInWorld((ProcId)flowId, FlowTag.None, null, identity, 0, RuntimeValue.Null, cb, cb2)`（`ProcId` 用 `(ProcId)int` 显式转换构造，ctor 是 private）。

4. **载档 API 的 NRE 行为**：`ListStorageMetas` / `TryGetLatestSaveSelection` / `LoadStorage` / `ListCurrentSaveSlots` 在未选 storage 时 NRE；本实现改用只读文件系统扫描绕开。若游戏版本升级，`RootSavePath` 结构与 `GetManualSlotId` 命名需复核。
5. **现场并发编辑**：委托方在同一源码树工作（新增 `ScrollRecon.cs`），期间出现两次编译错误，我改用 `KIMI\build_v7\` 镜像构建；最终在其修好后就地编译。**部署前请确认 DLL 来源**（当前 plugins 里已是委托方的 `28c41bb93b…`）。
