## 2. P1 性能下降调查与修复

### 2.1 测量方法（P1.0）

- 新增**独立测量插件** `KIMI\frameprobe\`（`FrameProbe.dll`，GUID `local.frameprobe`）：每帧只做 `列表 Add + 浮点加`，每 30 s 输出 `frames / dur / avg / p50 / p95 / p99 / max / fps`；额外记录 `>100 ms` 的长帧（带 `Application.isFocused`）与焦点切换。
- **为什么单独做一个插件**：计划的场景 B 是"插件不装"，但没有插件就没有帧率。把"测量仪器"与"被测对象"分开后，B/C/D 用**同一把尺子**，才能支撑"p95 偏差 ≤5%"这条验收。
- **剔除焦点假阳性**：Unity player 在失焦时停止渲染，恢复后的第一帧是纯墙钟时间。采样器把 `dt > 0.5 s` 的帧记入 `dropped` 而**不计入统计**，同时原样记进 `LOONGFRAME` 行并标注当时的 `isFocused`，因此"焦点造成的长帧"与"真实卡顿"可区分。
- 驱动脚本 `KIMI\v4_measure.ps1`（启动 → 轮询主窗口 → `AppActivate` 强制前台 → 静置 30 s → 采样 180/240 s，每 10 s 记录 CPU% 与 WorkingSet）+ `KIMI\v4_run_all.ps1`（A→B→D1→D2 连跑）。

**场景定义（对计划的一点必要调整）**

| 场景 | 定义 | 说明 |
|---|---|---|
| A | 无注入（直接跑硬链接 `WorldApart_kimi.exe`，不触发 IFEO） | 无帧率，比启动耗时与 CPU/WS |
| B | 注入链 + BepInEx + **仅测量插件** | 计划原文是"插件不装"；此处用"只装仪器"以便 D 能与之对比 p95 |
| C | 全装（P0 改名后、未做 P1.2 修复的版本：10 s 轮询 + 窗口常显） | 复现用户抱怨 |
| D1 | 修复版 + `MOD_PERF_LEGACY_PERIODIC=1`（把旧的 10 s 轮询强行开回来） | **同二进制 A/B 的关键** |
| D2 | 修复版默认行为 | 验收对象 |

### 2.4 修复内容（P1.2）

1. **删除周期性 re-apply**：`Update()` 不再定时 `ModSync.Apply`。变更触发只剩三条：用户 toggle（F10 / 设置页）、游戏自己调 `ModBootstrap.OnGameLoaded()`（Harmony postfix）、手动 "Re-scan + ApplyChanges" 按钮。
2. **`_show` 默认 `false`**；窗口打开时包列表 **1 Hz** 快照（`_snap` + `RefreshSnapshotIfDue`），IMGUI 事件不再逐次跨 interop 枚举。
3. **`ForceReloadTables` 去硬编码**：优先从 `ModConfigOverlay.PatchedTableNames` 取表名（它暴露的是 `IEnumerable` 代理，用非泛型 `Il2CppSystem.Collections.IEnumerator` 的 `MoveNext` 手动遍历，因为泛型 `IEnumerator<T>` 代理没有 `MoveNext`）；取不到才回落 `{tbnpcbasecfg, tbnpcaipersona}` 并在日志里注明来源（`ForceReloadTables(overlay: …)` vs `(fallback-literal: …)`）。
4. **`menu_patch` 退役**：`local.modmanager` 的 `units` 清空（`<M>` 与 `mod_template` 同步），其 `content/` 补丁负载删除，`tbmainmenubutton` 从回落清单移除。退役后 `ApplyChanges()` 返回 0 条（不再有 Reenter 级表），`ModSync` 的重进分支在稳态下不再被触发，toggle 直接走热表路径。
5. 保留 `MOD_PERF_LEGACY_PERIODIC=1` 作为性能 A/B 的复现开关（默认关）。

## 6. 遗留风险

1. **测量插件的处置**：`BepInEx\plugins\FrameProbe.dll` 是本次的**测量仪器**，不是功能插件。它会每帧做一次加法、每 30 s 写一行日志。正式交付前应移除（或保留以便复测——保留时它是 D2 场景的一部分，移除后 p95 只会更好）。
2. **P2 未做的两件事**：① "MOD 管理"行肉眼可见（待截图）；② 真实点击能否打开面板（接线已就位并记录 `wiring=added Button`，但未真点）。若点击无效，最可能是模板行的 `Image` 不是 raycast target——需要给新 `Button` 显式挂一个 `Image` 并设 `raycastTarget=true`。
3. **`Start` 钩子依赖时序**：`OnShow` 时 `SystemPage` 仍为 null，入口是在 `Start` 里注入的。如果某个版本 UI 生命周期变化（例如改为异步加载页面），需要改用"延迟重试"而不是固定挂 `Start`。
4. **S3 未拆分**：注入链整体让启动多花 1.46 s（2130→3594 ms），不满足计划的">2 s 才动手"门槛，故未改 `PreloadThread` 的优先级。若将来对启动耗时敏感，应单独量化 `TIME_CRITICAL` 与 1 s 自旋各自的贡献。
5. **`menu_patch` 退役的副作用**：主菜单"KIMI MOD 管理入口"按钮不再存在（该补丁负载已删）。若仍想要主菜单入口，需要重新加回 unit **并**额外处理 Reenter 表的"重进"路径——这正是 P2 走设置页而不是主菜单的原因。
6. **gpShell 风险不变**：v2 §E6 的三条禁区依然有效，本次未触碰。
7. **M1 的未决项**（详见 `剧情编辑器_m1侦察.md`）：RawFilePackage 的 `FileHash`/`FileCRC` 运行时校验未验证（决定"裸 mp4 原地覆盖"是否可用）；YooAsset PlayMode 未知（可能是 HostPlayMode，即远端可热更覆盖清单）；`segments.json` 的重读策略未知；`"cine/"+groupId+":"+clipId` 的拼接缺反汇编级证据。
8. **M1 的 keyFields 是**推断**出来的，不是读出来的**：没有导出到 Luban 的 schema/define 文件（`.xml` 只有 4 个 flow 文件），`.bytes` 头里有字段名但没有主键声明。8 张表存在"同样合理的备选主键"，10 张表 0 行因而无从验证。编辑器导出补丁前应对这些表做人工确认。
9. **M1 侦察过程中有一次约束违规（已修复并复核）**：一个子代理为验证 `A1BNDLHP` 包裹格式，把测试文件写到了 `WorldApart_Data\StreamingAssets\yoo\DefaultPackage\_strip_test.bundle`。子代理当场删除；主模型已独立复核——`DefaultPackage` 现为 **1,396 项 = 1,387 `.bundle` + 9 个元数据文件**，`grep -i -E "test|scratch|tmp|_strip"` 零命中；`RawFilePackage` 1,708 项（1701 mp4 + 7 元数据）完整。**现场已恢复原状，无残留**，但这类越界本应被前置约束挡住，记录在此。
