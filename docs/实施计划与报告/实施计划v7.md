## P0 三写入往返：真实存档实测（最高优先）

目标：把 S3 跳过的"任务/货币/属性/亲密度"写入在真实存档里跑通并验证持久化。

### 存档安全协议（先做）

1. 备份整个存档目录到 `KIMI\saves_backup_v7\<时间戳>\`（注册表路径不用管，只文件）。
   存档位置：`%USERPROFILE%\AppData\LocalLow\Nuverse\WorldApart\` 下的 saves 目录
   （先用 Everything/dir 确认实际子目录名再备份，别猜）。
2. 指定一个**专用测试存档槽位**，告知委托方用该槽位测试；测试期间不碰其他槽位。
3. 每次写测试前后各导一次对比快照（读出来打日志），失败可整体还原备份。

### 实现

4. 新增环境开关 `MOD_DEBUG_WRITETEST=1`（默认关）。F9 窗口在 CurrentPlayer!=null 时
   解锁四个写按钮（主菜单保持灰显+原因文本，沿用 S3 的灰显模式）：
   - 任务：对一个安全 questId（默认 1001 初到河望镇，可输入框改）推进 objective 进度
     （走游戏原生任务进度 API，S3 的 API 清单里挑有写语义的那个，禁止直接改表内存）；
   - 货币：对当前玩家加一个最小货币增量（+1），走背包/钱包 API；
   - 属性：改一项战斗属性 +/-1，走属性 API；
   - 亲密度：对一个在场 NPC +1，走亲密度 API。
5. 每次写入立即回读并打 `[DBG] WRITE ... before= after=`，再写存档（调用游戏原生存档接口，
   若存在）→ 重启游戏 → 载入该槽位 → 再读一次打 `[DBG] RELOAD ... value=`，
   三次值一致即"写入往返"通过。
6. 委托方人工环节：载入测试槽位、点按钮、看游戏内 UI 数值变化、重启验证——
   报告里给出逐步操作清单和预期日志行。

### 验收

- 三个写入往返全部值一致；游戏内 UI 同步变化（委托方截图）。
- 还原备份后存档完好（游戏能载入、值回原样）。

## P1 空间传送落地

目标：F9 输入 spaceId → 游戏中实际切换空间。

### 路线（按优先级，每条先写 30 分钟侦察再动手）

A. **调用点借参**：Harmony 钩住游戏内"地图旅行"点击链上创建 ProcContext 的那个方法
   （从 GotoSpaceCommand 的调用方反查，s3_rva.py 同款反查），postfix 里把目标 spaceId
   换成 F9 设定的值。等于"让游戏自己造上下文，我们只改目的地"。
B. **更低层入口**：从 API 清单找空间切换的下层 API（SpaceManager/SceneLoader/EnterSpace 类），
   确认能否用存档上下文 + spaceId 直接调。
C. **兜底**：程序化驱动游戏自带地图 UI（找到 MapPanel 的旅行按钮点击处理直接 Invoke）。

- 实现后 F9 传送区灰显解除，输入 spaceId（旁边放常用 ID：客栈大堂 10001/比武场 12006…，
  直接引用 `KIMI\release\example_template\常见ID速查表.md` 的值，别复制错）。
- 验收：载入测试存档 → 传送 10001 → 委托方截图场景 + 能正常存档/离开。

## P2 剧情跳跃（flow 级）

目标：F9 搜任务/剧情 → 跳到指定剧情位置（执行对应 GameActionFlow）。

1. 从 API 清单找 flow 执行入口（FlowRunner/Execute 类，RVA 表里有），
   确认入参能否在存档上下文构造。
2. 落地后为 P0 任务写入提供第二种验证途径（跳到一个任务中段再推进）。
3. UI：F9 新增"剧情跳跃"区，搜索框（复用 S3 搜索）+ 任务树（questId→flows），
   双击执行，执行前强制提示"已自动备份存档"。
4. 验收：跳到"11124 上等的食材"中段 → 委托方确认任务追踪/UI 状态正确。
