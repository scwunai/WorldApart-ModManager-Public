## S1. MOD 标签定位修复

### S1.0 问题定义（委托方截图实证）
v5 注入的 `MODTab` 渲染位置错误：不在左侧标签列（音量/显示/系统）下方，而是出现在对话框**底部**（"提交反馈"按钮旁），文字浮在框外。v5 日志显示兄弟 tab 的 localPosition 全是 `(0,0)`、`MODTab` 被 `Maintain()` 写成 `(0,-100)`——**兄弟 tab 的位置显然由别的东西决定**（UPF 布局系统或烘焙坐标），照抄"相对列容器偏移"的思路本身就不成立。

### S1.1 取证要求（先搞清楚兄弟 tab 怎么定位，再动手）
1. 运行时打印：列容器 `Frame#0` 与每个 `Frame#navX` 的 `RectTransform` 全套参数——`anchoredPosition / anchorMin / anchorMax / pivot / sizeDelta / rect`，以及容器和 tab 上的**具体组件**（用逐个 `GetComponent<T>` 探测已知类型：LayoutGroup/LayoutElement/ContentSizeFitter/CanvasGroup，**不要**再用 `GetComponents(Type)` 全量枚举——v5 因此触发 coreclr `0xc0000005` 已有留痕）。
2. 回答：兄弟 tab 的纵坐标到底来自哪里？（a）UPF 布局组件驱动；（b）烘焙的 anchoredPosition 全在容器原点但视觉上分列（不可能，截图证明分列）；（c）容器有 ContentSizeFitter/LayoutGroup 在运行时重排。
3. 定位方案按取证结论选：**优先复刻兄弟的定位机制**（若 UPF 布局驱动，找到该布局的刷新入口让它把新节点重排进去；若烘焙坐标，则从 `navSystem` 的**实际渲染 rect** 计算偏移：`y = navSystem.rect.yMin - 高度`，同时复制 anchor/pivot/sizeDelta，并 `SetSiblingIndex(navSystem 的 index + 1)`）。

### S1.2 验收标准
委托方截图：`MOD 管理` 标签位于左侧标签列、系统设置正下方一格，与兄弟 tab 同宽同高对齐；点击仍接 `ShowPanel()`（S2 完成后改为切页）；日志无 Error。

## S2. 原生 MOD 管理页（核心需求：游戏内样式、不开额外窗口）—— **委托方自行实施，实施模型勿动**

> 2026-10-06 决定：本任务由委托方亲自实施（需要多轮截图迭代，实施模型无全模态能力）。实施模型的任务范围只有 S1 与 S3。
> 本节保留作为实现规格与验收标准。实施模型**不得**修改 SettingsEntryHook 的切页/面板相关逻辑（S1 只做标签定位修复，点击行为保持现状），以免与委托方的 S2 改动冲突。

### S2.0 需求（委托方原话）
"MOD管理按钮点开还是 BepInEx 的菜单样式并且还是额外的窗口配置，希望能使用游戏本身的样式在游戏的设置内配置，不开额外窗口。"

### S2.1 实现规格
1. **新建 MOD 管理内容页**：`pageShell`（ScrollRect 内容区）内新增第 5 个页面容器（克隆 `SystemPage` 的结构作底，或新建空容器带与兄弟页一致的 RectTransform 参数），命名 `MODPage`。
2. **行模板用真 Toggle 行**：系统设置页第一行"使用自定义 AI 模型"带**可工作的原生 Toggle**（v5 侦察确认该行有 Toggle 组件）——克隆它作为 unit 行模板：每行 = 包标题 + unit 说明 + Toggle。样式因此天然与游戏一致。
3. **行内容**：遍历 `PackageSnapshot()`，每 unit 一行——左侧标签 `unitId [类型]`，右侧 Toggle 状态 = `IsEntryEnabled`；`onValueChanged` → 复用现有 `Apply(modId, unitId, npc, value)` 核心（含 `ModSync` + `SelfCheck`）。页面打开时 1Hz 刷新状态（节流，沿用 `_snap` 模式）。
4. **切页接线**：`MODTab` 点击改为切到 `MODPage`（把四个原生页 `SetActive(false)`、`MODPage.SetActive(true)`；兄弟页容器从 v5 侦察已知在 ScrollRect Viewport 下）。**关键防串台**：钩 `SettingsPanelViewModel.NavTo`（RVA `0x1C62ED0`，v5 已反汇编：它调 `set_ActivePage` + `SmoothScrollTo`）的 Harmony postfix——只要切到的是原生页且 `MODPage` 开着，就 `SetActive(false)` 掉 `MODPage`。这样原生三个 tab 永远恢复原生行为。
5. **摘除 IMGUI 外窗入口**：`MODTab` 不再调 `TogglePanel()/ShowPanel()`；IMGUI 窗口降级为**纯 F10 调试入口**（保留，默认隐藏）。管理面板的"对外形态"只有设置页内的原生页。
6. 若 `MODPage` 因 ScrollRect 滚动区域大小需要适配，按兄弟页的实际尺寸参数复制；不追求滚动（unit 数量现阶段 ≤ 数十）。

### S2.2 验收标准
1. 委托方截图：设置页内 MOD 管理页与原生页风格一致（同一行模板、同一 Toggle 样式）；标签列四 tab 位置正确（S1）。
2. 委托方操作：Toggle 关闭 `basecfg_patch` → 档案页标记消失（可配合 `SELFCHECK` 日志）；再开恢复。**全程无 IMGUI 窗口弹出**。
3. 原生三个 tab 切换正常互不干扰；日志无 Error。

## S3. 剧情跳跃调试工具（local 剧情跳跃测试 mod）

### S3.0 需求（委托方原话）
"实现一个剧情跳跃测试 mod，实现便捷跳跃到具体的剧情位置并自定义编辑玩家的各种参数，包括数值以及各种 NPC 的社交，以方便调试。"

定位：开发调试工具，非用户功能。**UI 允许用 IMGUI**（按 F9 开关，与 F10 调试窗并列；不进设置页、不追求原生样式），但所有逻辑放在 `LocalModManager` 插件内独立 `Debug` 区域，不污染管理器主路径。

### S3.1 侦察（先做，产出 API 清单写进报告）
在 `dump.cs` / `il2cpp_out` + `il2dis.py` 查明以下运行时 API（类名/方法签名/调用前提）：
1. **任务系统**：`QuestManager` 类——接受/完成/放弃任务的方法、按 questId 查询任务状态、任务接取 NPC/场景字段（`tbquest.acqNpcID` 等）。
2. **流程系统**：`FlowRuntimeManager`（v5/M1 已知 `LoadFlowsAndTranslateQuestTable`）——启动指定 flow/proc 的入口。
3. **场景/传送**：space 切换或玩家传送 API（tbspace 相关管理器）。
4. **玩家数值**：货币/属性/背包的数据容器（GameData/PlayerData 类）及修改入口。
5. **NPC 社交**：运行时亲密度容器（`tbnpcintimacy` 的阶段规则 + 当前值存储），按 npcId 读写的方法。
6. **AI 对话触发**（可选加分项）：直接向指定 NPC 发起对话/注入上下文的方法。

### S3.2 实现规格
F9 打开调试窗口（默认隐藏），三个页签：
1. **剧情跳跃**：任务搜索框（按 id/名称模糊匹配 `ConfigManager.Tables.TbQuest`）→ 选中后操作按钮：`接受任务` / `完成当前步骤` / `完成任务` / `传送到接取 NPC`（按 S3.1 侦察到的 API 组合实现，哪步做不了就如实灰掉并注明原因）。
2. **玩家参数**：货币、主要属性、常用消耗品数量的读取与修改输入框（侦察到的字段为准，能改多少算多少）。
3. **NPC 社交**：NPC 搜索（复用任务搜索的模糊匹配思路）→ 亲密度当前值显示 + 输入新值写入。
- 所有改动**只写运行时状态**，不落补丁、不改存档文件；窗口顶部固定红字提示"调试改动会随存档保存，重要存档请先备份"。
- 每个操作打日志（操作前/后状态值），失败时把异常写日志不崩游戏。
- 开关：默认启用；`MOD_DEBUG=0` 可整体禁用（防误触）。

### S3.3 验收标准
1. 委托方实测三件套各一项：跳转到指定任务（任务日志/接取状态可见变化）、修改货币（游戏内 UI 显示变化）、修改某 NPC 亲密度（人物面板显示变化）。
2. 操作日志完整（前后值）；非法输入（不存在的 id 等）不崩溃、有日志。
3. 不开启时（F9 未按）对游戏零额外开销（窗口隐藏即早退，参考 P1 的 `_show=false` 路径）。
