> 编写时间：2026-10-07。因运行环境迁移而作此交接。
> 工作目录 `<G>` = `C:\Program Files (x86)\Steam\steamapps\common\<游戏目录>`；一切过程产物放 `<G>\KIMI\`。
> 存档目录 `<S>` = `%USERPROFILE%\AppData\LocalLow\Nuverse\WorldApart\StorageV1\1.0`。

## 1. 项目一句话

给 Steam 游戏《不问凡尘》（WorldApart，Unity 2022.3 IL2CPP + gpShell 壳）建立一套完整的第三方 MOD 环境：注入 BepInEx → 插件提供游戏内 MOD 管理页 + F9 调试窗 → MOD 以补丁包形式改表/换资源 → 打包发布到创意工坊（publishedFileId 3814675406）。

## 2. 整体架构

```
玩家双击 启动MOD版.bat
  └─ wastart.exe (IFEO 调试器, KIMI\injector\)
       └─ CreateProcess 挂起 WorldApart_mod.exe
       └─ 注入 modprobe.dll → LoadLibraryW
            └─ 自行 LoadLibraryW(GameAssembly.dll)，在返回瞬间
               把 il2cpp_init 前 16 字节改绝对跳转（probe6 方案，与调用者零竞态）
                 └─ 钩内还原字节 → 调原始 il2cpp_init → 重装钩
                 └─ 复刻 doorstop 的 CoreCLR bootstrap
                      └─ BepInEx 6.0.0-be.788 (原为 be.697，元数据 31.1 只认 be.788)
                           └─ 生成 interop\ 154 个程序集
                           └─ 加载 LocalModManager.dll（插件，源码 KIMI\bepinex_plugin\）
                                ├─ Harmony 钩：ModBootstrap.OnGameLoaded 监视
                                ├─ 设置页注入：SettingsPanel.OnShow/Start postfix
                                │    → 克隆 navSystem 标签 → MOD 管理第 5 页
                                │    → 页内克隆"使用自定义 AI 模型"行模板（原生 Toggle）
                                │    → 页根挂 ScrollRect 吸收滚轮 + Harmony 拦 ScrollRect.OnScroll
                                │      （防滚轮沿父链被游戏 ScrollRect 截获切标签）
                                ├─ ModSync：ApplyChanges → 清 tableBytes 缓存
                                │    → ModBootstrap.OnGameLoaded() → ForceReloadTables
                                ├─ F9 IMGUI 调试窗（DebugTool，MOD_DEBUG=0 关闭）
                                └─ F10 旧 BepInEx 配置窗（保留，默认隐藏）
游戏侧 MOD 管线（原生）：
  <M>\<包>\mod.json + units → EnumerateIn(<unitRoot>\tables\*.patch.json)
  → hot 表热重建 / Reenter 表需重进 → ConfigManager.Tables
```

**关键架构事实（反汇编实证，勿再踩）**：
- 游戏 exe / UnityPlayer.dll / GameAssembly.dll 的 IAT 被 gpShell 整体剥离成 gpShell.dll 存根——doorstop 4.3 的 iat_hook 永远匹配不到，这是当初"看似卡死"的根因。改 gpShell IAT 会弹 Failed to load il2cpp；改 GameAssembly EAT 游戏从不调用；LdrRegisterDllNotification 零触发。**唯一可行路线就是 probe6 的 il2cpp_init 抢占钩**。
- EnumerateIn 粒度是**目录**不是 unit：补丁必须放 `<unitRoot>\tables\`，一个 unit 一个目录；目录不存在时静默返回空 List，failure 都不写。
- ApplyChanges 返回值是"需重进的表集合"而非应用条数；只要 tbmainmenubutton（Reenter 表）启用，热重建就被整体跳过。
- 视频替换三级缓存：Bundle 加载扫 sidecar → Bank 加载无条件读 → _bankLoads 命中闸门。换视频不用重启进程，关开面板即重读；但 cine 走 AssetBundle 里 CommonVideoClip.segmentVPath，只改 segments.json 不会被播到。
- A1ResourceSystem 有原生 SetExternalPackageResolvers 扩展点（优先级高于内置包），是干净的 Mod 资源路线；明确是"DLC 通道"，别当 MOD 资源根。
- IL2CPP 共享折叠桩陷阱：get_CurrentSpaceId/get_CurrentSpaceUuid 走折叠桩，interop 直调抛异常。**所有钩子和直调按"类型全名+方法名"解析，不得用 dump RVA 当唯一标识。**
- 载档 API（ListStorageMetas 等）未选 storage 时 NRE，需用只读文件系统扫描绕开。

## 7. 硬约束与工作规则（继续有效）

- 工作目录必须在 `<G>`；产出物放 `KIMI\`。
- **不使用 subagent 做任何插件实施**——我只写实施计划 + 验收，动手的是用户协调的"实施模型"；打包 / bat / 文档 / 清理我直接做。
- 发布包内任何用户可见字符串 / 文件名 / 日志**零 kimi**；`A1\KIMI` 目录名不动；插件 csproj 必须有 `<DebugType>none</DebugType>`。
- bat：GBK + CRLF + 引号；中文路径下的 .ps1 必须 UTF-8 带 BOM。
- **bash 处理中文路径/文件名不可靠**：文件操作一律 Python；zip 一律 Python zipfile。
- 实施模型约定：报告必须含可复跑的日志证据、如实记未达成项、部署物与产物 MD5 一致、备份被替换的文件。
