## 1. 需求（委托方原话）

"实现一个剧情跳跃测试 mod，实现便捷跳跃到具体的剧情位置并自定义编辑玩家的各种参数，包括数值以及各种 NPC 的社交，以方便调试。"

定位：**开发调试工具，非用户功能**。UI 允许用 IMGUI（按 **F9** 开关，与 F10 调试窗并列；不进设置页、不追求原生样式）。所有逻辑放 `LocalModManager` 插件内独立 `Debug` 区域。

## 2. 侦察（先做，产出 API 清单写进报告 §3.1）

在 `KIMI\il2cpp_out\dump.cs`（约 190 万行）+ `KIMI\il2dis.py` 查明以下运行时 API（类全名/方法签名/调用前提/字段偏移），每条注明证据（dump.cs 行号或反汇编 RVA）：

1. **任务系统**：`QuestManager` 类——接受/完成/放弃任务的方法、按 questId 查询任务状态、任务接取 NPC/场景字段（`tbquest.acqNpcID` 等）。
2. **流程系统**：`FlowRuntimeManager`（v5/M1 已知 `LoadFlowsAndTranslateQuestTable`）——启动指定 flow/proc 的入口。
3. **场景/传送**：space 切换或玩家传送 API（tbspace 相关管理器）。
4. **玩家数值**：货币/属性/背包的数据容器（GameData/PlayerData 类）及修改入口。
5. **NPC 社交**：运行时亲密度容器（`tbnpcintimacy` 阶段规则 + 当前值存储），按 npcId 读写的方法。
6. **AI 对话触发**（可选加分项）：直接向指定 NPC 发起对话/注入上下文的方法。

## 3. 实现规格

F9 打开调试窗口（默认隐藏，挂 `ManagerBehaviour`，仿照 F10 `_show` 早退模式：未开启时零开销），三个页签：

1. **剧情跳跃**：任务搜索框（按 id/名称模糊匹配 `ConfigManager.Tables.TbQuest`）→ 选中后操作按钮：`接受任务` / `完成当前步骤` / `完成任务` / `传送到接取 NPC`（按侦察到的 API 组合实现，**哪步做不了就如实灰掉并在界面注明原因**，不得伪造可用）。
2. **玩家参数**：货币、主要属性、常用消耗品数量的读取与修改输入框（以侦察到的字段为准，能改多少算多少）。
3. **NPC 社交**：NPC 搜索（复用任务搜索的模糊匹配思路）→ 亲密度当前值显示 + 输入新值写入。

硬性要求：
- 所有改动**只写运行时状态**，不落补丁、不改存档文件；窗口顶部固定红字提示"调试改动会随存档保存，重要存档请先备份"。
- 每个操作打日志（操作前/后状态值），失败时把异常写日志不崩游戏。
- 开关：默认启用；`MOD_DEBUG=0` 环境变量可整体禁用（防误触）。
- 新增代码命名空间/风格与 Plugin.cs 现状一致；注释用英文（文件现状如此）。

## 4. 验收标准（委托方实测）

1. 三件套各一项实测通过：跳转到指定任务（任务日志/接取状态可见变化）、修改货币（游戏内 UI 显示变化）、修改某 NPC 亲密度（人物面板显示变化）。
2. 操作日志完整（前后值）；非法输入（不存在的 id 等）不崩溃、有日志。
3. F9 未按时对游戏零额外开销（窗口隐藏即早退）。
4. v4/v5 基线无回退（SELFCHECK marker 照常、日志无新 Error）。
