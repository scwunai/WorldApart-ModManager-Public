## P1 空间传送路线 B（本计划主体，对应未闭环汇总 M5）

目标：`GotoSpace` 系列传送后**世界重建、玩家真实到达目标空间**，测试传送功能可用，
F9「空间传送」按钮对真实空间（10001 客栈大堂）端到端可验证。

### 步骤

1. **证据复习**（不动手先读）：`实施报告v9.md` §2.2 失败样本与读数窗口、
   `实施报告v7.md` §7.2 路线 B 原始规格。
2. **反汇编先行**：对三件套做反汇编核实，写 recon 结论（各方法签名、调用前提、
   与 `GotoSpace` 的差异——特别是**谁驱动加载等待面板与世界重建时序**）：
   - `GotoSpaceInstance`（目标空间实例的入口）
   - `ResolveSpaceHandler`（空间句柄解析）
   - `TryPrepareSpaceEnterAction`（备选：进入动作预处理）
   反汇编对象用游戏自己的程序集；只读，不改任何游戏文件。
3. **路线实施**：按 recon 结论在 `DebugActions` 传送路径实现路线 B，优先级
   `GotoSpaceInstance` + `ResolveSpaceHandler` → `TryPrepareSpaceEnterAction` 备选。
   F9「空间传送」按钮入口不变；按钮顺序改为先试路线 B，失败时输出明确拒绝原因
   （不静默回退旧 `GotoSpace`——旧路线已证伪，保留只会再拆一次世界）。
   如需新增游戏程序集引用，改动 csproj 并在报告改动清单声明。
4. **自动化复测**：沿用 v9 修正后的 harness（`OnGameLoaded` + 世界会话齐备）+
   `MOD_DEBUG_LOADSLOT=auto_02` + `MOD_DEBUG_TESTSTORAGE=6b372e77-e282-43b4-ab14-db9f38a57935`
   只读载入 + 全程 `SuppressAutoSave`；目标空间 10001，观察窗 140 s（沿用 v9 窗口）。
   通过读数：`CurrentSavedSpaceUuid` 恢复非空、`CurrentPlayer != null`、
   `visited(10001)=True`、传送后可正常继续游玩（不再触发后续异常）。
5. **路线排除纪律**：若路线 B 仍失败，逐条记录反汇编依据 + 失败样本原始日志
   （同 v7 §3 / v9 §2.2 规格），并给出 M5 新路线侦察的下一步建议；不允许无证据换路线。

### 验收

- 传送提交后 ≤140 s 世界重建且玩家真实到达 10001，可正常继续游玩；
  before/after 日志 + 世界状态读数齐全；帧数据不回退（p95 ≤5% 偏差、稳态 dropped=0）；
  全部运行 `[Error`=0。
- 报告附路线排除过程：反汇编结论 → 采纳理由 → 通过证据链（或失败样本）。
