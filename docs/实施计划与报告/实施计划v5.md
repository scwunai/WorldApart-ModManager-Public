## Q1. 设置页 MOD 入口重做（P2 收尾，需求已按委托方实测反馈修正）

### Q1.0 问题定义（委托方 2026-10-06 实测反馈，取代 v4 的"修复克隆行"思路）
1. **点击无反应**：v4 注入到 SystemPage 内容区的那行 "MOD 管理" 不是可点击内容。
2. **形态不对**：委托方要求入口做成**左侧标签列的第四个标签**（与 音量设置 / 显示设置 / 系统设置 同列同样式），位置在**系统设置下方**——不是右侧内容区的一行。
3. v4 注入的 SystemPage 残留行（`MODEntry`）应摘除，避免双入口。

### Q1.1 侦察与取证（先取证再动手）
1. 打印左侧标签容器结构：层级路径、布局组组件及参数（Spacing/padding/childAlignment）、每个标签 tab 的完整组件清单——`Button`（onClick 绑定了什么）、`Image`（sprite/color/raycastTarget）、`TextMeshProUGUI`（color/fontSize/alignment）、**选中态/悬停态的表现机制**（是换 sprite/color，还是有独立高亮子节点被激活）。
2. 打印 tab 点击 → 页面切换的链路：是调 `SettingsPanelViewModel` 的 `GotoAudio/GotoDisplay/GotoSystem` 之类方法，还是直接激活对应 `RectTransform` 页面？（dump.cs 里 `SettingsPanelViewModel` 有 `AudioPage/DisplayPage/ControlPage/SystemPage` 四个 RectTransform 属性与 `GotoSystem()` 等方法，先反汇编 `Goto*` 看实现。）
3. 样式一律**运行时从兄弟 tab 采样**（常态文字色、背景、字号；选中态如可采样也采样），不硬编码。

### Q1.2 实现
1. 克隆"系统设置" tab 节点 → 命名 `MODTab` → 文本改 `MOD 管理` → 追加到标签容器末尾（系统设置下方，布局组会自动排）。
2. 接线：克隆 tab 自带的 `Button.onClick` 换成打开管理面板（`ManagerBehaviour.Instance.TogglePanel()`）；点击回调加日志 `[SETTINGS] MOD tab clicked`。
3. 命中：确保克隆 tab 的 `Image.raycastTarget=true`、尺寸与兄弟 tab 一致（布局组内自动）。
4. 摘除 v4 的 `MODEntry` 行注入（`SettingsEntryHook` 里 SystemPage 克隆行逻辑删除或改为 no-op 清理旧残留——注意有人机器上可能已有旧 `MODEntry` 节点，做个 Find+Destroy 的一次性清理）。
5. 回归：重开设置页两次，确认不重复添加（`Find("MODTab")` 去重）；原三个 tab 切换功能不受影响。

### Q1 验收标准
1. 委托方截图：左侧标签列为 音量设置 / 显示设置 / 系统设置 / **MOD 管理**，样式与兄弟 tab 视觉无差别，位于系统设置正下方。
2. 委托方点击 MOD 管理：管理面板打开（插件日志 `MOD entry clicked`/`MOD tab clicked` + 面板 Toggle 日志）；点击其他 tab 正常切换、互不干扰。
3. `BepInEx\LogOutput.log` 无 Error；SystemPage 内容区无 v4 残留行。

## Q2. 视频替换路线验证（实验任务，不写正式功能）

### Q2.0 背景（M1 结论，直接采信）
- 技能 CG 之外的视频全部走 `(groupId, clipId)` 数字寻址，**改表无法换内容**，只能换资源字节。
- `RawFilePackage` = 1,701 个裸 mp4（2.9 GB）；`MergedVideoResources~/` = 1,134 mp4 + 1,132 segments.json；DefaultPackage bundle 的 24 字节包裹格式已破译。
- **引擎原生扩展点**：`GameResourceManager.SetExternalPackageResolvers(asset, rawFile)` 注册的 resolver 优先于内置包，`NotOwned` 自动回落（RVA `0x79E5D0` 反汇编证实）。视频走 `LoadRawFileForVideoPlayer(location, …)`（RVA `0x79E240`）。
- 四个未决项（M1 §④）：① RawFilePackage 运行时是否校验 FileHash/FileCRC；② YooAsset PlayMode；③ segments.json 重读策略；④ `"cine/"+groupId+":"+clipId` 拼接的反汇编级证据。

### Q2.1 实验 E-V1：外部解析器路线（核心实验）
写一个**一次性实验插件**（可并入 LocalModManager 的实验命名空间，或独立 dll，命名不含 kimi；用环境变量 `MOD_EXP_VIDEO=1` 启用）：
1. 准备测试视频：取一段短小 mp4（5–10 秒，明显可辨识的画面，比如纯色+大字幕），放到 `<M>\local.expvideo\` 下。
2. 插件启动后构造 `ExternalPackageResolver` 委托：location 命中测试目标时返回 `Resolved` 并提供从测试目录加载的 `ResourcePackage`；其余一律 `NotOwned`。**`ResourcePackage` 的构造方式是本实验最大未知点**——先反汇编/查 YooAsset 2.3.9 的 `ResourcePackage`/`ResourcePackageLoad` 相关 API（`KIMI\tools\a1res_api.txt` + dump.cs + il2dis.py），搞清"从磁盘目录构造一个可读 raw file 的包"的最小路径；若 `ResourcePackage` 构造不可行，记录失败证据并转 E-V1b：直接内存垫 `LoadRawFileForVideoPlayer` 的 location 参数做重定向（次选，改动面更大）。
3. 目标视频选一个**容易在游戏里触发**的：优先从 `tbskillshow.cg_path` 的 67 个技能 CG 里挑（可配合表补丁改指向，触发条件明确）；若技能 CG 触发困难，选 MergedVideoResources 里拍卖演出之类主流程必经的片段，或退而求其次验证 `ResolveExternalRawFilePackage` 是否被视频加载路径调用（在 resolver 里记日志，先证明"走到这"，再证明"换成功"）。
4. 观测：resolver 命中日志（location 原文）→ 游戏内实际播放内容。证据 = 委托方截图/录屏 + 日志。

### Q2.2 实验 E-V2：FileHash/FileCRC 校验（静态为主）
翻 YooAsset 2.3.9 源码（GitHub 有对应 tag，可走 ghfast.top 镜像）+ 反汇编游戏内 `RawFilePackage` 加载路径，回答：加载裸文件时是否比对清单里的 `FileHash`/`FileCRC`。这决定"原地覆盖 mp4"路线（不依赖注入）是否成立。**只出结论与证据，不做实际覆盖。**

### Q2.3 实验 E-V3：segments.json 重读策略
改一个**测试用** `MergedVideoResources~` 分组的 segments.json（先备份原文件到 `KIMI\`），把某 clip 的 EndPTS 改小，播放观察画面是否提前截断；玩完恢复原文件。回答"每次播放重读 vs 启动缓存"。若证实重读，M3 的"追加帧"路线可行；若缓存，记录结论即可。

### Q2 验收标准
- E-V1：**至少证明 resolver 被视频加载路径调用**（日志级）；能换成功画面为完全达成。若 `ResourcePackage` 构造走不通，给出反汇编证据与备选（E-V1b 或原地覆盖）的对比建议。
- E-V2/E-V3：各一段结论 + 证据（源码引用/反汇编/实测日志）。
- 全部实验不得修改 gpShell/GameAssembly/UnityPlayer/exe；E-V3 对游戏目录的唯一改动（segments.json）必须当场恢复并验证字节一致。
- 产出写入 `KIMI\实施报告v5.md` 的 Q2 章节，并回填 `KIMI\剧情编辑器设计.md` §5.3（路线决策从"待定"变"已验证"）。

## Q3. 剧情编辑器 M2 只读查看器

### Q3.0 依据（M1 机读产物，直接消费）
- `KIMI\m1_out\`：510 个提取产物（259 表 JSON + 247 bytes + 4 flow.xml）；`_inventory.json`。
- `KIMI\m1_keyfields.json`：259 表主键（230 单字段 / 19 复合）。
- `KIMI\m1_story_map.json`：剧情聚合（36 章节组 / 实体与边 / 5 条未决）。
- `KIMI\剧情编辑器设计.md` §4 架构（Python 后端 + 本地 Web 前端）与 §8 M2 验收标准。
- **两个必须处理的坑**（M1 §⑤）：`tbquest.overrides` 15 条维度变体（M2 至少标注存在，默认展示 METAL/默认文案）；Luban JSON 裁 null 字段——**schema 以 dump.cs 为准**（M2 若做字段说明，从 dump.cs bean 取字段全集，JSON 缺字段显示" null"占位）。

### Q3.1 交付物
新建 `KIMI\story_editor\`：

```
KIMI\story_editor\
  backend\
    store.py        # 表仓库：加载 m1_out JSON，原始快照只读；字段全集从 dump.cs bean 补（可选，M2 可降级为 JSON 字段）
    model.py        # 实体装载：NPC(含persona)/StoryNode(quest按taskGroup分章)/Dialogue/VideoRef；规则读 m1_story_map.json + m1_keyfields.json
    refindex.py     # 引用索引：npcId/questId/flowId/视频地址反查
    serve.py        # Flask，仅绑 127.0.0.1
  frontend\
    index.html      # 三页签：剧情脉络图 / 人物 / 视频库
    app.js          # 图谱用 ECharts 或 Cytoscape（本地 vendor，不引 CDN——游戏机器不一定有外网）
  run.bat           # 一键启动（激活 venv → python serve.py → 开浏览器）
```

**范围红线**：M2 只读。不做任何编辑、不做导出、不写游戏目录。多语言默认 zh-Hans，切换器留给 M3。

### Q3.2 功能最低要求
1. **剧情脉络**：按 `taskGroup` 36 组分章列表；章内任务链以节点图渲染（节点=quest，边=`tbgameactionflow.nextIds` 或 objectives→flow 的局部图）；点击节点下钻显示任务名/描述/对白入口。**图规模可控**（ quest 1875 行全画会糊，默认按组过滤）。
2. **人物**：1592 行 NPC 列表（搜索/按域过滤），详情页含档案字段 + 人格 speakStyle 全文 + 关联 quest 反查。
3. **视频库**：三类来源清单（RawFilePackage 1701 / MergedVideoResources 1134 / 技能 CG 67）+ 引用反查（哪个表哪行引用它；`(groupId,clipId)` 类显示"需换资源字节"提示，技能 CG 显示"可改表重定向"提示）。
4. **对账**：启动自检打印 各实体计数 vs 表行数（如 quest=1875、npc=1592、persona=1156），写进验收日志。

### Q3 验收标准
1. `run.bat` 一键打开浏览器，三个页签可用，无后端 Error。
2. 对账日志：quest 1875 / npc 1592 / persona 1156 / 视频 1701+1134 与表行数一致（±设计文档注明的例外）。
3. 委托方抽查：苏倾盏（100000）详情页人格文本与游戏内一致；某任务节点能看到关联对白；某视频能看到引用它的表行。
